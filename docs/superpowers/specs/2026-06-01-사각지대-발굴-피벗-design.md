# 사각지대 발굴 피벗 — 설계 문서

- 날짜: 2026-06-01
- 상태: 설계 확정(구현 전) · 스펙 리뷰 1회 반영
- 대상 코드베이스: KoreanSim (`backend/` FastAPI + `frontend/` React/Vite)

## 1. 배경과 목적

현재 프로젝트는 사실상 **정책 사전 여론조사**에 가깝다. 프리셋이 사형제·동성결혼 같은 가치 쟁점이고, 갤럽 여론(Prior)을 페르소나에게 주입해 "여론에 저항하는지"를 보는 방법론 실험 구조다.

이 프로젝트를 최초 기획안(`흑백_기획서_초안`)의 비전으로 되돌린다:

> **정책 담당자가 혼자 생각했을 때 놓치기 쉬운 집단·우려·사각지대를, 실제 정책안을 대상으로 발굴하는 탐색 보조 도구.**

입력은 거창한 가치 쟁점이 아니라 **실제 집행형 정책안**(대상·신청방식·제외조건이 있는)이고, 출력은 시행 시 생길 부작용·사각지대·예상 민원이다. 여론조사 대체가 아니라 *추가 검토가 필요한 지점을 빠르게 발견*하는 보조 자료다.

성공 기준: **담당자가 혼자서는 못 떠올렸을 집단/우려가 결과에 드러나는가.**

## 2. 범위

### 2.1 제거
- 프리셋 프레이밍 변형 체계(중립/긍정/부정 × 맥락 유무 × 개방형/척도형). `frontend/src/data/presets.json`의 실험 변인 프리셋.
- 갤럽 Prior 주입 일체:
  - `backend/app/services/prior_service.py`
  - 프롬프트 데이터 `backend/app/data/priors/*.json` (※ 저장소 루트 `data/gallup/`는 원본 PDF 자료일 뿐, 실제 소비 경로는 `app/data/priors/`)
  - `render_prior_text()`, `build_agent_prompt`의 `[여론 참고]` 블록, `SYSTEM_PROMPT_OPENAI`의 여론 참고 문구
  - `SimulateRequest.topic_id` (prior 선택 키 — 제거/중립화)
- "여론 분포"를 헤드라인으로 두는 표출(찬반 비율 % 강조).

### 2.2 추가/변경
- 자유 텍스트 정책안 입력 + LLM 구조화 패스.
- 응답(LLM 출력 dict)에 `expected_complaint`(예상 민원) 필드 추가.
- **기존 인라인 합성 패스 확장** (신규 서비스/엔드포인트 없음 — §5).
- 원응답을 프론트 결과뷰까지 전달(대시보드 원문 카드·필터 enabler).
- 데이터 전용 대시보드(해석·점수 없이 집계만).

### 2.3 비범위 (이번에 하지 않음)
- 연령×집단 히트맵 (작은 n으로 노이즈, 정밀 과장 → 폐기).
- 심각도/위험도 점수, 자동 코멘트, KPI 요약 카드 줄.
- 정책 수정 전·후 비교(향후 별도 스펙).
- 표본 상한 확대(현행 `n_agents` 최대 100 유지).
- `caveat` 필드 표출: 이번 범위는 **사각지대=`blind_spot`** 에 집중. `caveat`(일반 유보점)은 중복을 피해 노출하지 않음(향후 별도 블록 검토).
- **백엔드 영속 저장소/run-id 도입**: 합성을 인라인 유지하기로 결정(§5)했으므로 불필요. "재실행 없이 분석만 재수행"은 이번 목표가 아니다.

## 3. 입력 — 자유 텍스트 + LLM 구조화

담당자가 정책 초안을 **자유 텍스트**로 입력하면, LLM `구조화 패스`가 인터뷰에 필요한 정보만 중립적으로 정리한다. 원칙: 정책의 문제점을 미리 판단하지 않고, 인터뷰 수행에 필요한 정보만 구조화한다.

### 3.1 `structured_policy` 출력 계약
구조화 패스는 다음 JSON을 1회 반환한다(필드별 값 + 그 값이 입력에 명시됐는지 LLM이 메웠는지):

```json
{
  "policy_name": {"value": "string", "source": "stated|inferred"},
  "target":      {"value": "string", "source": "stated|inferred"},
  "apply_method":{"value": "string", "source": "stated|inferred"},
  "exclusions":  {"value": "string|null", "source": "stated|inferred"},
  "context":     {"value": "string|null", "source": "stated|inferred"}
}
```

- `source`는 항목별 enum 두 값(`stated`=입력에 명시, `inferred`=LLM이 보충)으로 표현한다. 대시보드는 `inferred` 항목을 시각적으로 구분 표기(§6 헤더).
- 인터뷰 생성에는 `value`만 사용한다(정책 텍스트 구성). `source`는 표출·감사용.

### 3.2 실패 fallback
구조화 패스가 파싱 실패/타임아웃이면 구조화를 건너뛰고 **원문 자유 텍스트를 그대로** 정책 본문으로 사용한다(전 항목 `source=stated`로 간주, `policy_name`=입력 첫 줄 또는 "제목 없음"). 구조화 실패가 전체 실행을 막지 않는다.

### 3.3 전달·저장
- 1단계 실행 시작 시 `structured_policy`를 산출하고, **SSE `policy_structured` 이벤트**로 1회 내보낸다(에이전트 응답 스트림보다 먼저).
- 프론트는 이를 `currentRun.structuredPolicy`(sessionStorage, §6.3)에 저장해 결과뷰 헤더에서 사용한다.

## 4. 응답 스키마

응답은 Pydantic 모델이 아니라 **plain dict**로 흐른다(요청 모델 `SimulateRequest`만 schemas.py에 있음). 따라서 필드 추가는 프롬프트 JSON + 파서 + SSE 페이로드 + 합성 입력 포맷터에 분산된다(§8).

### 4.1 유지 (현행 `llm_client.py` 출력)
`stance`(찬성/중립/반대), `stance_strength`, `rationale`, `caveat`, `blind_spot`, `affected_group`, `reframing`, `persona_link{direct, inferred}`.

중요한 현실:
- `blind_spot`/`affected_group`은 **엄격한 3조건(직접성·특수성·비중복성)을 만족할 때만 채워지고 자주 null**이다. 따라서 사각지대 묶음의 인원수는 **전체 표본이 아니라 사각지대를 실제로 말한 응답자 수**가 분모다. 표출 시 "100명 중"이 아니라 "사각지대를 언급한 N명 중"으로 정직하게 표기한다. → 합성 단계에서 "해당 필드가 non-null인 응답자 수"를 분모로 계산해 함께 반환한다.
- `caveat`는 찬성/반대와 무관하게 더 자주 채워지는 "가장 큰 유보점"이다. 사각지대(blind_spot)와 구분되는 신호이며 이번엔 미표출(§2.3).

### 4.2 추가
- `expected_complaint`: "시행 후 이 페르소나가 실제로 제기할 문의/불만 한 문장. 없으면 null." 예상 민원 블록의 원천. 전용 판정 규칙(`EXPECTED_COMPLAINT_RULES`)을 `CAVEAT_RULES`/`BLIND_SPOT_RULES`와 같은 형식으로 추가한다.
- **null 통일 규칙**: `parse_agent_response`는 다른 옵션 필드와 동일하게 **값이 없으면 key를 omit**한다(현행 관례). downstream(SSE 페이로드·합성 입력 포맷터·프론트)은 **key 부재 = null**로 일관 처리한다.

### 4.3 응답 레코드 배선
대시보드 페르소나 카드용으로 다음 페르소나 필드를 **SSE 페이로드 → currentRun → 프론트 타입**까지 전달한다(현재 `age_group/gender/region_group`로 coarsen되어 일부만 전달됨):
`age, gender, province, district, occupation, family_type`.
데이터는 `persona_repository.py`의 `REQUIRED_COLUMNS`/`structured_profile`에 이미 로드됨 — 배선은 sampler 이벤트 + response 이벤트 + currentRun 저장 + 프론트 타입 4곳에 걸친다(원라이너 아님).

## 5. 합성 — 기존 인라인 패스 확장

### 5.1 현실 (리뷰 반영)
합성은 **이미 인라인으로 작동 중**이다. `simulate.py`는 모든 응답을 모은 뒤
`build_summary_llm_payload` → `stream_openai_summary_clusters` → `summary_from_text` → `normalize_summary`
를 호출해 `concern_clusters`/`support_clusters`/`blind_spot_clusters`(각 `agent_ids`, 개수 정합, 리필 패스 포함)를 만들고, 그 결과로 `aggregate`의 빈 클러스터 배열을 **덮어쓴다**(`simulate.py:297-299`). 즉 blind_spot 클러스터링은 새로 만드는 게 아니라 **이 기존 패스를 확장**하는 일이다. (이전 설계의 "빈 배열을 채운다"는 서술은 오류였다.)

### 5.2 확장 내용 (교체 아닌 병행)
기존 계약(`agent_ids`/`count`/`short_title`/`blind_spot_examples`)은 **이름·동작 그대로 유지**한다(테스트 `test_normalize_summary_*`가 고정). 그 위에 **필드를 추가**하고, 신규 묶음 종류를 더한다. 산출 묶음 4종:

1. **반복된 우려(사각지대)**: non-null `blind_spot` 클러스터링 — 기존 `blind_spot_clusters` 확장.
2. **예상 민원**: non-null `expected_complaint` 클러스터링 — 신규 묶음 배열(`complaint_clusters`).
3. **지목된 집단**: 자유 서술 `affected_group`을 정규 집단으로 클러스터링(단순 groupby 아님; "가족과 사는 청년"/"부모랑 사는 20대" 병합).
4. **입장 분포**: `stance` 단순 집계(`compute_aggregate.total`, 합성 불필요).

각 묶음에 **추가**되는 필드:
- `denominator`: 해당 필드가 non-null이었던 응답자 수(§4.1). 표출 분모.
- `representative_quote`: **대표 라벨로 쓸 실제 발언 원문**(LLM 요약 아님). 묶음의 **검증된 `agent_ids` 중 한 명**의 해당 필드 텍스트를 **그대로** 쓴다.
  - 선택 규칙(결정적): ① 묶음 발언들의 중앙값 길이에 가장 가까운 발언, ② 동률이면 **가장 작은 agent_id**를 tie-breaker로 한다. 재실행해도 같은 입력이면 같은 결과.
- `inferred_based`: §5.3 정의에 따라 계산한 boolean.

**id 무결성(P0-2 정정)**: 기존 reconciliation을 **유지**한다 — `normalize_summary`가 `actual_ids`에 없는 id를 조용히 제거하고 count를 보정([llm_client.py:663-664](backend/app/services/llm_client.py:663), 테스트 고정). hard-fail로 바꾸지 않는다. 무결성 보장은 *"표출되는 `representative_quote`·count·필터 대상은 전부 살아남은 검증된 `agent_ids`에서만 나온다"* 이다(날조 금지 ≠ 드리프트 시 전체 실패). 따라서 `representative_quote`는 reconciliation **이후**의 id 집합에서 고른다.

기존 `short_title`/`label`/`compact_korean_label`(LLM 요약 라벨)은 §6.2 원칙에 따라 **표출에서 사용하지 않는다**(verbatim으로 대체). 계약 호환을 위해 필드는 남기되 대시보드가 렌더링하지 않는다.

### 5.3 `inferred_based` 정의 (P1-5 정정)
`persona_link.inferred`는 boolean이 아니라 **자유 텍스트 설명**이라 "의존 비율"의 안정적 근거가 없다. 따라서 안정적 proxy로 재정의한다:

> 한 응답이 *추론 의존*이라 함은 `persona_link.direct`가 비어있거나 없고(`clean_optional_text`가 None) `persona_link.inferred`가 비어있지 않은 경우.

묶음의 `inferred_based`는 (추론 의존 member 수 / `count`) ≥ 0.5 일 때 true(임계값 설정 상수). 이 proxy조차 신호가 약하다고 판단되면 **태그를 제거**하는 것을 허용한다(표출 원칙상 과장보다 생략이 안전).

## 6. 대시보드 — 데이터 전용

상단에 고정 안내 문구:
> "실제 의견수렴을 대체하지 않습니다. 아래는 가공·평가 없이 모델 응답을 집계한 결과이며, 해석은 담당자의 몫입니다."

### 6.1 블록 구성 (위→아래)
1. **헤더**: 정책명(구조화 추출) + "페르소나 N명".
2. **입장 분포**: 찬성/중립/반대 원수치 막대. 우려/반발로 나누지 않음.
3. **반복된 우려(사각지대)**: `blind_spot` 묶음(`caveat` 아님 — §2.3). 각 묶음 = `representative_quote`(verbatim) + 인원수 막대 + (해당 시) "추론 기반" 태그. 클릭 → 원문 필터.
4. **예상 민원**: `expected_complaint` 묶음. **하나씩 패널로 분리**(알약 배지 아님). 각 패널 = `representative_quote`(verbatim) + 인원수. 클릭 → 원문 필터.
5. **불리하다고 지목된 집단**: 집단명 + "N명 지목" 횟수. 비율·위험도 없음.
6. **페르소나 응답 원문**: 카드. `나이·지역·직업·가구형태` + 입장 태그 + 발언(rationale/blind_spot). 위 묶음 클릭 시 `member_ids`로 해당 원문만 필터.

### 6.2 확정된 표출 원칙 (결정 사항)
- **의미 부여 금지**: 심각도/위험도/우선순위 점수, 자동 해석 코멘트, KPI 요약 줄 모두 없음.
- **라벨은 LLM 요약이 아니라 페르소나 실제 발언(verbatim)**. 묶기 위한 최소 그룹화만 LLM이 하고, 보여주는 문구는 데이터 그대로.
- **숫자는 탐색 신호**: 모든 묶음 인원수는 비결정적(재실행 시 변동)이며 정답이 아니다. 큰 숫자로 강조하지 않고 막대/소형 수치로만 표기.
- **분모 정직성**: 사각지대·집단 묶음은 "해당 항목을 말한 응답자 수"(`denominator`)가 분모임을 표기.

### 6.3 결과뷰 데이터 전제 (리뷰 반영)
**source of truth = `currentRun`(현재 `sessionStorage` 사용 — `localStorage` 아님, P1-7 정정).** 현재 `currentRun`은 `aggregate`+`sampledAgents`만 저장하고 **페르소나별 원문(rationale/blind_spot/expected_complaint/persona_link/인구통계)을 저장하지 않는다.** 6.1의 원문 카드(6)와 묶음→원문 필터는 이 원응답이 결과뷰에 있어야 가능하다. 따라서 다음을 `currentRun`에 추가한다:
- `responses`: 페르소나별 원응답 배열(인구통계 6필드 포함, §4.3).
- `structuredPolicy`: §3.3.

용량: 100응답×텍스트 ≈ 수백 KB. sessionStorage 한도(브라우저별 ~5MB) 내. 한도 초과 시 표본 상한이 100이라 실질 위험 낮음.
별도로 **저장된 실험**(`experimentStorage`, localStorage)에도 원응답을 포함할지는 이번 범위에서 결정: 포함한다(저장 실험 재조회 시에도 동일 대시보드 렌더 가능). 용량 우려 시 원응답은 currentRun에만 두고 저장 실험은 집계만 유지하는 축소안을 Phase 4에서 택일.

### 6.4 저장·불러오기 라운드트립 (시연 1급 요구)
**요구**: 피벗 이후 새로 저장한 실행은, 불러왔을 때 **저장 시점과 동일한 새 대시보드**로 렌더링되어야 한다(시연 시나리오: 실행→저장→불러오기→동일 대시보드).

- **복원 소스 = `.json` 스냅샷**(CSV 아님). 스냅샷은 이미 `results[].responses`(원응답) + `aggregate`를 직렬화하므로, §4·§5의 신규 필드를 응답/집계에 추가하면 스냅샷에 자동 포함된다.
- **반드시 스냅샷에 포함**: 페르소나 원응답(`expected_complaint` + 인구통계 6필드 포함), 신규 클러스터 계약(`complaint_clusters`, `representative_quote`, `denominator`, `inferred_based`), 그리고 **`structured_policy`**(응답/집계에 없으므로 `ExperimentSnapshotInput`에 필드 신설).
- **불러오기 → 새 대시보드 배선**: 현 `loadSnapshot`은 실험/런 화면으로 복원한다. 불러온 스냅샷이 **새 ResultPage 대시보드**로 표출되도록 경로를 추가한다.
- **CSV 갱신**: 복원 소스는 아니나, `experimentCsv.ts` 헤더에서 제거 대상 컬럼(`preset_id`, `real_source/real_year/real_*`)을 빼고 신규 필드를 반영해 export가 깨지지 않게 한다.
- **구버전 파일 비대상**: 피벗 이전 저장 파일의 하위호환은 범위 밖(사용자 확인). 마이그레이션 불필요.

## 9. 단계 분해 (구현 계획용)
- **Phase 1 (제거 — FE+BE 동시, 저위험 아님; P0-3 정정)**: Prior/프리셋 제거는 백엔드만으로 끝나지 않는다. 백엔드(`[여론 참고]`/`render_prior_text`/`prior_service`/`app/data/priors`/`SimulateRequest.topic_id`)와 **프론트의 결합**(`topic_id` 전달, `real_opinion`/prior 표시, preset 변형 의존 타입·저장·CSV·비교 UI)을 함께 정리해야 stale 코드가 안 남는다. 먼저 프론트의 prior/preset 의존 지점을 조사·목록화한 뒤 FE+BE를 한 단위로 제거. 백엔드·프론트 테스트 동시 회귀.
- **Phase 2 (응답 강화)**: `expected_complaint` 추가(§8, null=omit 관례) + 인구통계 6필드 end-to-end 배선 + 원응답·`structuredPolicy`를 `currentRun`(sessionStorage)에 저장(§6.3). 대시보드의 enabler.
- **Phase 3 (합성 확장)**: 기존 인라인 합성 패스에 **필드 추가(병행, 교체 아님)**(§5.2) — `complaint_clusters`, affected_group 클러스터링, `representative_quote`(verbatim+결정적 tie-break), `denominator`, `inferred_based`(§5.3). reconciliation 동작·기존 테스트 보존.
- **Phase 4 (대시보드 재구성)**: `ResultPage.tsx` 데이터 전용 재구성, 묶음 클릭→원문 필터 배선, 저장 실험 원응답 포함 여부 택일(§6.3), Playwright 검증.
- **Phase 5 (저장·불러오기 라운드트립 — 시연용, §6.4)**: 스냅샷에 `structured_policy` 신설 + 신규 필드 포함 확인, `loadSnapshot`→새 대시보드 경로 배선, `experimentCsv.ts` 헤더 갱신(prior/preset 컬럼 제거). 실행→저장→불러오기→동일 대시보드를 Playwright로 검증.
- **횡단(구조화 패스)**: §3 구조화 패스는 Phase 1 이후 아무 때나 추가 가능하나 헤더 표출(§6.1)·`structuredPolicy` 저장과 함께 Phase 2에 묶는다.

## 10. 검증 관점
- reconciliation 보존: unknown id 제거+count 보정 동작과 `test_normalize_summary_removes_unknown_agent_ids_and_corrects_count`가 그대로 통과하는가.
- 표출 무결성: `representative_quote`가 **검증된 agent_id member의 원문과 글자 단위로 일치**하는가(요약 혼입·날조 금지). 묶음 클릭 필터 대상이 모두 검증된 id인가.
- `representative_quote` 선택의 **결정성**: 같은 입력 재실행 시 동일 발언(중앙값 길이 + 최소 agent_id tie-break)을 고르는가.
- blind_spot/affected_group/expected_complaint가 모두 null인 표본/부분 null에서 대시보드가 빈 상태·정확한 `denominator`를 정직하게 표시하는가.
- `expected_complaint` null=omit 관례가 파서·SSE·합성 입력·프론트에서 일관되게 부재=null로 처리되는가.
- Prior/preset 제거 후 **백엔드·프론트 양쪽** 회귀(프롬프트, 타입, 저장, **snapshot/CSV export**(`exports.py`), 비교 UI)가 없는가 — export 페이로드가 신규 클러스터 계약으로 깨지지 않는지 포함.
- 브라우저 가시 동작(묶음 클릭 → 원문 필터, `inferred` 정책 항목 구분 표기)은 Playwright로 확인.
- **라운드트립(§6.4)**: 실행→저장→불러오기 후 대시보드가 저장 시점과 동일하게 렌더(예상 민원·structured_policy 헤더·인구통계 카드 포함)되는가. 스냅샷에 `structured_policy`·`expected_complaint`·신규 클러스터 필드가 실제로 직렬화되는가.
